# 설계 초안 06 · DB에서 v1 조회 페이지 만들기

글: 만들기 · 의료 · Codex · 2026-10-27

**상태: 리드 검수·사용자 선택 전 초안이에요. 화면 생성 코드·테스트·DB·워크플로는 만들거나 실행하지 않았어요.** 지금은 시안 v5를 제품 화면으로 바꾸는 범위와 공개 경계를 제안해요.

현재 구현을 읽은 기준은 작업 가지 `work/fhir-line-05-dbt-quality@1b554be`예요.

## 1. 문제

시안 v5는 기대 결과 파일에서 값을 읽고 과거 변이 시험·Git 기록의 사본을 보여 줘요. 현재 제품은 R1~R4 수정 뒤 셀 차이를 찾고 실행마다 CSV를 남겨요. 따라서 시안의 예전 설명을 현재 제품의 동작으로 쓰지 않고, 실제 DB와 현재 실행 기록에서 화면을 만들어야 해요.

`runs/index.csv`는 실행 시각·커밋·상태·차이 건수만 갖고 있어요. 과거 모든 실행의 세부 JSON이나 DB 스냅샷을 보존하는 구조는 아니에요. 게다가 Python 시험이나 dbt가 먼저 실패하면 check.sh가 사다리에 도달하지 않아 이번 index 행이 없을 수 있어요. 이전 성공 JSON만 읽고 이번 실행이 성공했다고 표시해서는 안 돼요.

## 2. 목표와 하지 않는 것

승인 뒤에는 명령 하나로 로컬의 DB 조회 결과·검증 상태·이력을 담은 정적 HTML을 만드는 것이 목표예요. 지표 값은 `bp_summary`·`fct_bp_person`에서 읽고, expected는 검증용으로만 읽어요. expected의 값을 화면의 실제 결과로 채워 넣지 않아요.

첫 추천은 A/B 조회이고 A′는 파생 출처로 기존 DB·검증에 보존해요. A+A′를 합산하지 않고 두 병원의 환자를 통합한 전체 비율도 만들지 않아요. 실제 로그인·서버 운영·AI 질의·원본 FHIR 통째 보기·CSV 전체 공개·Pages 게시·일정 설정은 첫 화면 구현과 분리해요.

## 3. 대안과 대가

| 대안 | 바뀌는 파일·운영 | 데이터·시험의 대가 | 판단 |

## 4. 화면 범위와 읽는 표

화면정의서 0.3의 ID는 S00~S07로 여덟 개예요. 로그인 S00을 제외한 기능 화면 일곱 가운데 **v1은 S01~S05를 추천**하고 S06·S07은 뒤로 미뤄요. 이는 구현 완료 상태가 아닌 범위 제안이에요. 실행 이력은 S04 안에서 먼저 보여 주고, 제품 코드의 변경 이력과 혼동하지 않아요.

|---|---|---|
| S00 로그인 | 제외 | 로컬 시연은 S01에서 시작해요. 비밀번호 입력을 받는 가짜 인증을 만들지 않아요. |
| S01 지표 현황 | 포함 | `bp_summary`의 A/B 4행을 읽어요. 정의·기준 시점·마지막 검증 시각을 붙여요. B의 연말은 환자별 기준 연도이므로 일괄 2025-12-31이라고 쓰지 않아요. |
| S02 대상 환자 조회 | 로컬에 포함 | `fct_bp_person`의 병원·시점·혈압·판정·사유를 허용 목록으로 내보내요. 원래 person_id는 내부 연결에만 써요. 이름·나이·원천 ID는 화면이나 숨긴 데이터에도 넣지 않아요. |

## 5. 바뀌는 데이터 모양과 실행 순서

현재 DB 모델·키·고정 경로는 유지해요. 새 Python 내보내기와 정적 HTML이 후보이며, 아래 파일은 아직 만들지 않았어요.

| 후보 파일/객체 | 최소 계약 |
|---|---|
| `scripts/render_report.py` | 정해진 DB·출력 경로를 받아 명령 하나로 실행할 후보예요. 임의 SQL·URL을 받지 않고 DB를 read_only로 열어요. |
| `.local/.../ui-runs/<run_id>/run-manifest.json` | 시작/종료·단계별 상태·제품 커밋/dirty·정의 버전 근거·검증 범위·공개용 payload 해시를 기록할 제안이에요. 기존 runs/index.csv의 열을 바꾸지 않아요. |
| `public_summary`, `public_people`, `public_trace`, `public_checks` | DB/검증 결과에서 허용한 필드만 생성한 화면용 객체예요. 원래 행·JSON을 브라우저에 복사하지 않아요. |
| 같은 실행의 HTML·안전한 JSON과 최근 완료 위치 | 실행별 폴더를 따로 쓰고 검사가 끝난 묶음만 선택해요. 공개용 묶음과 로컬 상세 묶음은 다른 생성 모드·디렉터리로 나눠요. |

제안한 순서는 다음과 같아요.

1. 이번 실행 ID와 시작 상태를 만들고 입력/출력 경로를 확인해요. expected·원본·보호 경로와 겹치면 쓰기 전에 실패해요.
2. 검증의 실제 종료 상태와 같은 실행의 결과 파일을 모아요. dbt 이전 실패나 사다리 미실행을 이전 성공으로 채우지 않아요. 과거 index 행은 있는 요약만 보여 주고, 당시 세부 상태가 없으면 미확인으로 남겨요.
3. DB 조회와 A/B의 기존 기대값 비교를 **같은 읽기 전용 트랜잭션**에서 실행하는 내보내기 경계를 만들어요. 함께 판정할 품질 SELECT도 그 connection에서 실행해야 해요. 나머지 시험·고정·A′ 상태는 제품/입력 해시·시각·검증 범위를 대조해 구분하고, 이번 DB와 연결하지 못하면 미확인으로 표시해요. 과거 check.sh가 본 DB와 나중에 읽은 DB가 같다고 단순 추정하지 않아요. 기존 비교 함수는 connection을 받지만 최상위 check 함수는 현재 고정 DB를 열므로, 이 연결 경계는 별도 구현·시험이 필요해요.
4. 허용한 값만 새 객체로 만들고 HTML을 임시 실행 폴더에 생성해요. 그 객체의 해시와 검증 상태를 같은 run manifest에 묶어요. 정의 05가 먼저 수용되면 고정 manifest를 연결하고, 아직 없으면 정의 버전 미고정이라고 표시해요. 버전 값을 임의로 붙이지 않아요.
5. HTML·JSON 누출 검사와 값 대조를 통과한 묶음만 최근 완료 결과로 선택해요. 동시 생성은 같은 선택 파일의 잠금·교체 순서를 검증해야 해요. 실패 실행은 현재 실패 상태와 이전 성공의 시각을 구분하고, 이전 숫자에 이번 성공 표시를 붙이지 않아요.

실패/경고/미실행을 구분하고, 마지막 성공·이번 시도 시각을 함께 보여 줘요. 오래됨의 자동 판정 기준은 운영 주기를 정한 뒤 정해야 해요. 현재 index는 모든 단계의 실행 이력과 완전한 과거 스냅샷이 아니며, 새 manifest로 소급 보완했다고 표시하지 않아요.

## 6. ID를 내보내지 않는 경계

R1의 `public_report`·`public_cell`과 같은 **허용 목록으로 새 객체를 만드는 원칙**을 사용해요. 기존 함수가 환자 상세의 모든 필드를 이미 지원한다는 뜻은 아니에요. 새로운 코드·단위·상세 값에는 형식과 허용 집합이 있는 별도 화면 계약과 검수가 필요해요.

`public_report`는 사다리 부분에 사용하고, dbt의 pass/warn/error/skipped 상태는 별도 허용 집합에서 화면 상태로 옮겨요. 원래 dbt 결과 객체를 그대로 넘기거나, 경고·미실행을 기존 사다리 상태로 잘못 바꾸지 않아요.

- 원래 person_id·OMOP person_id·source_row_key·reference·파일명·원본 JSON·자유로운 오류 설명은 HTML, JSON, DOM 속성, URL, 로그에 내보내지 않아요. 앞 8글자나 해시 ID로 바꿔 그대로 내보내는 방식도 쓰지 않아요.
- 내부에서만 사람 키와 화면용 환자 번호를 연결해요. 환자 번호는 병원·실행 안의 별칭이며 장기 동일성이나 익명화를 보증하지 않아요. 연결 실패 시 원래 ID를 대체 표시하지 않아요.
- 사유는 현재 허용된 판정 문구만 쓰고, 혈압·코드·단위는 검증한 필드만 내보내요. `value_source_value` 같은 임의 문자열을 통째로 보여 주지 않아요. HTML/JSON 삽입과 스크립트 종료 문자열도 안전하게 처리해야 해요.
- 같은 날 소수·부분값과 NULL을 보존해요. 날짜·수치가 드물면 다른 공개 자료와 연결될 수 있으므로 ID 마스킹만으로 공개를 승인하지 않아요.

## 7. 시험과 기대 결과

| 확인 | 승인 뒤 구현에서 요구할 결과 |
|---|---|
| DB가 실제 값의 출처인가 | 수제 DB의 값을 바꾸면 화면의 실제값도 바뀌고 검증은 불일치가 돼야 해요. expected의 값으로 실제값을 덮어 통과시키지 않아요. |
| v1 요약 | 기존 고정 CSV의 A 3/5→4/6, B 4/9→3/9와 화면용 객체·표시값이 같아야 해요. A 연말 0.6667은 66.67%, B 연말 0.3333은 33.33%라는 기존 화면 표기와 대조해요. |
| 사람·상세 | 기존 사람별 행/키/값과 일치해야 해요. 124/92의 기존 비조절 판정, 같은 날 성분별 최솟값·부분값·혈압 없음·동률 출처·연결 누락을 별도 입력으로 확인해요. |
| 분모 0 | 기존 규칙의 분모 0·분자 0·rate NULL을 유지하고 대상 없음으로 표시해요. 현재 저장 요약에 실제 0분모가 있다고 주장하지 않아요. |
| 실패와 이력 | 검사 도중 중단, 이번 index 없음, manifest/DB/payload 불일치, dirty 커밋, 손상된 index, 실패와 이전 성공의 공존을 확인해요. |
| 개인정보·화면 | ID가 자유로운 오류 설명이나 숨긴 속성에 있어도 내보내지 않아야 해요. 전체 HTML·JSON·링크·다운로드를 검사하고 브라우저로 조회·필터·상세·실패 상태를 확인해요. |

기존 expected와 리드의 셀 차이 다섯 사례는 읽기만 해요. 새 화면 상태의 기대값은 구현 담당과 다른 세션에서 먼저 준비하고 리드가 검수해요. 지금 이 초안은 새 기대값을 작성하거나 고정하지 않아요.

## 8. 공개 조건 · 위험 · 비용 · 되돌리기

GitHub Pages는 정적 결과를 게시하는 후보예요. 공식 한도는 사이트 1GB, 배포 10분, 월 대역폭 100GB의 소프트 한도예요. 무료 공개 저장소에서 사용할 수 있지만 서버 앱이나 민감한 비밀번호 전송용으로 쓰지 않아요([공식 한도](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), 10/27 확인). 원천·DB·환경 전체를 올리지 않고 집계·검증 상태·정의 근거만 별도 묶음으로 만드는 안이에요.

기존 [공개·운영 조사](/home/junhyun/personal/builds/medical-data-hands-on/thinking/research/public-run-1027/README.md:34)의 일정 지연·누락, 아티팩트 로그인·보존 제한, ODbL 조건을 재사용해요. 공개 산출물의 최종 법적 분류와 제공 묶음은 미확인이므로, 로컬 화면 구현 승인을 공개 승인으로 읽지 않아요.

| 항목 | 경계·담당·복구 |
|---|---|
| 비용 | 지금은 문서만 작성하며 설치·DB 실행·유료 호출이 없어요. 미래 로컬 생성은 기존 설치·메모리/5GB 상한을 따르고 구현 담당이 실제 시간·HTML/JSON 크기를 측정해요. Pages/Actions 게시·계정 사용량·알림은 별도 승인과 확인이 필요해요. |
| 보안 | 정해진 읽기 전용 질의와 보호 경로 검사, 출력 허용 목록, 실패 시 성공 무효화가 강제 지점이에요. 출력 경로의 symlink/hardlink, 중단·동시 실행은 구현 담당이 반례로 확인하고 리드가 검수해요. |
| 개인정보 | 로컬의 환자 상세와 공개 집계를 분리해요. 공개 모드에서는 환자 객체 자체를 생성하지 않아, CSS로 숨긴 상세가 남지 않게 해요. 실제 기관명·주소·원천 ID와 개인정보가 있는 자유 문자열은 제외해요. |
| 되돌리기 | 새 묶음의 선택을 중단하고 이전 검증된 묶음을 선택해요. 실패 근거와 이전 성공은 보존하고 임시 파일 정리와 복구를 구분해요. 구현 담당이 상태·해시를 확인하고 리드가 대조해요. 공개 뒤 복제된 사본·이미 사용한 자원은 되돌릴 수 없어요. |
